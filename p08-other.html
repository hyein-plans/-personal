01 — 캠페인 데이터 CRM 고도화 · 공개 제한

모으는 과정을
등록하는 과정으로 바꿨습니다.

판매처·채널별 캠페인 데이터를 본사가 수작업으로 취합·가공한 뒤 결과를 확인하던 구조를, 표준 엑셀로 업로드하면 시스템이 가공·집계하고 캠페인·키워드 기준으로 조회·비교하는 구조로 바꿨습니다.

01.1
기존과 개선 비교
같은 데이터를 확인하기까지의 흐름입니다.
Before수작업 취합
판매처 · 채널별 분산→담당자 제출→본사 수작업 취합 · 가공→결과 확인

결과 확인까지 약 2~3일

After표준 업로드 · 자동 집계
엑셀 양식 입력→업로드→시스템 가공 · 집계→캠페인 · 키워드 기준 조회

본사 지표 확인 시점 당일

data check lead time약 2~3일 → 당일본사의 데이터 취합 · 가공 · 결과 확인 기준
01.2
제가 판단한 범위 — 조회와 비교 구조
캠페인 조회 화면과 성과 비교 구조를 기획했고, 요구된 형태 대신 목적에 맞는 방식을 제안했습니다.
요구
갤러리형 조회
여러 캠페인을 한 화면에 모아 보는 방식
판단
목적은 성과 비교
한눈에 보는 것보다 캠페인끼리 비교하는 것이 목적
제안
상세 팝업 여러 개 열기
목록에서 상세 팝업을 여러 개 열어 나란히 비교
!업로드 양식 전체, 데이터 매핑 전체, 집계 산식 전체를 제가 단독으로 정의했다고 확장하지 않습니다. 클릭률 · 전환율 상승 같은 수치는 쓰지 않았습니다.

02 — 퍼스트몰 · 운영 개선

실패한 건만
다시 작업할 수 있게 만들었습니다.

회원 목록을 일괄 업로드해 쿠폰을 발급할 때 일부 데이터는 실패할 수 있습니다. 운영자가 결과를 빠르게 확인하고 실패한 대상만 다시 작업할 수 있는 흐름을 설계했습니다.

01
회원 목록 업로드

02
성공 / 실패 확인

03
실패 목록 다운로드
실패 ID와 사유 확인
04
같은 양식으로 재작업

정의한 기준
실패 사유중복 데이터와 회원 매칭 실패를 구분해 확인
결과 표시성공과 실패를 나눠 표시하고, 실패 대상만 추려 재작업
!구현 완료 여부가 명확하지 않은 부분은 운영 흐름과 정책 · 화면 설계 수준으로 표기했습니다.
