at a glance
WHY · 왜 필요했나

온라인 주문만으로는 어느 매장이, 언제, 무엇을 확인하고 상품을 내어줄지가 정해지지 않았습니다.

WHAT · 무엇을 했나

서비스 정책과 사용자 화면, 매장관리 화면을 기획하고 QA를 맡았습니다.

HOW · 어떻게 했나

네 주체의 일을 한 장에 겹쳐 놓고, 상태가 다음 주체에게 넘어가는 시점을 맞췄습니다.

RESULT · 결과

주문부터 바코드 수령까지 이어지는 신규 서비스를 기획하고, 개발 · POS 연동을 거쳐 오픈했습니다.

01 — why

온라인 주문만으로는
매장에서 할 일이 정해지지 않습니다.

주문이 들어와도 어느 매장이 준비하는지, 언제 준비가 끝났다고 보는지, 고객이 무엇을 들고 오면 상품을 내어줄 수 있는지가 정해져 있지 않으면 현장에서 업무가 멈춥니다.

01
살 수 있는지 판단할 기준이 없다

매장의 실제 재고를 보지 않고 주문을 받으면, 준비할 수 없는 주문이 매장으로 넘어갑니다.

02
준비 완료 시점이 모호하다

고객에게 언제 “오셔도 됩니다”라고 알릴지가 정해져 있지 않으면 헛걸음이 생깁니다.

03
정상 흐름만으로는 부족하다

재고 부족, 미방문, 취소, 연동 결과 미수신 같은 상황에서 누가 무엇을 하는지도 정해야 했습니다.

02 — what

각자의 역할과
상태 전달 시점을 정의했습니다.

서비스 정책, 사용자 화면, 매장 담당자의 관리 화면을 기획하고 QA를 맡았습니다.

매장 조회 · 선택

재고와 거리 조건에 따라 픽업 매장을 조회하고 선택하는 흐름

픽업 주문서 · 상태

수령자 정보 항목과, 주문 상태와 매장 준비 상태의 연결

알림 시점 · 내용

준비 완료 안내 시점과 문자 내용, 안내 링크 구성

매장관리 기능

신규 주문 확인 · 상품 준비 · 바코드 확인 · 픽업 완료 처리

역할 · 권한

본사 · 관리자와 매장 담당자의 역할과 처리 권한 정의

03 — how

네 주체의 일을
한 장에 겹쳐 설계했습니다.

고객, 쇼핑몰, POS, 매장 담당자가 각각 어느 시점에 무엇을 하는지를 나란히 두고, 상태가 넘어가는 지점을 맞췄습니다.

03.1
스윔레인 — 주문에서 수령까지
강조한 칸이 다음 주체에게 상태가 넘어가는 지점입니다.
단계를 눌러 보세요
고객customer
매장 · 상품 확인→주문→준비 완료 안내 확인→매장 방문→바코드 제시→상품 수령
쇼핑몰mall
POS 재고 확인→구매 가능 판단→주문 생성→주문 상태 반영→고객 안내
POSpos
주문 · 상품 · 바코드 수신→매장 처리→픽업 완료 결과 전달
매장 담당자store
신규 주문 확인→상품 준비→준비 완료→고객 바코드 확인→상품 전달
✓고객이 보는 안내와 매장이 하는 준비가 같은 상태를 기준으로 움직이도록 맞췄습니다.
!흐름도에는 주문을 직접 처리하는 네 주체만 표시했습니다. 본사 · 관리자의 역할과 매장별 권한은 별도로 정의했습니다.
03.2
주문 조건과 연동 데이터
무엇을 주고받는지를 방향별로 정리했습니다.

픽업 처리 결과완료 상태
주문 · 안내 기준
주문 단위동일 매장 상품을 기준으로 주문
구매 가능 판단POS 재고 기준, 주문 전 재고 부족 시 구매 차단
고객 안내매장의 준비 상태를 기준으로 안내 시점 · 내용 · 마이페이지 · 주문 바코드 노출
03.3
예외 시나리오
정상 흐름에서 벗어났을 때의 처리 기준을 함께 정의했습니다.
발생 단계주문준비안내방문결과
01재고 부족
주문 전 재고가 부족하면 구매를 차단하고, 재고 복구 후 재주문할 수 있도록 분기
02미방문
픽업 준비가 끝났으나 고객이 방문하지 않은 경우의 처리 기준
03취소
주문 취소 시 재고와 주문 상태의 처리 기준
04연동 결과 미수신
POS 처리 결과가 돌아오지 않은 경우의 상태와 확인 방법
05회원 · 비회원
주문 주체에 따른 안내 경로와 바코드 확인 방식의 차이
!일부 재고 부족 · 부분 처리 규칙은 최종 운영 정책으로 단정하지 않았습니다.
04 — result

주문부터 수령까지 이어지는
신규 서비스를 오픈했습니다.

개발과 POS 연동을 거쳐 서비스를 오픈했습니다.

신규 O2O 서비스 출시

온라인 주문부터 매장 수령까지 이어지는 픽업 주문 서비스를 구축하고 연동을 완료했습니다.

고객–매장 업무 연결

고객이 보는 안내와 매장이 하는 준비가 같은 상태를 기준으로 움직이도록 맞췄습니다.

운영 기준의 구체화

구매 가능 판단, 안내 시점, 바코드 확인 같은 현장 판단 기준을 정책으로 정리했습니다.

예외까지 포함한 설계

재고 부족·미방문·연동 실패 상황의 처리 기준을 함께 정의했습니다.

직접 확인한 주문은 테스트 건이며, 이용량 · 매출 같은 성과로 바꾸어 쓰지 않았습니다.

05 — output

주요 산출물

실제 작업 문서에서 가져온 화면입니다. 개인정보와 거래 데이터는 가림 처리했습니다. 이미지를 누르면 크게 볼 수 있습니다.
